# Search-friendly WordPress publishing

An SEO plugin can manage selected metadata and sitemap output. It cannot establish that every page has useful content, correct status codes and consistent product facts. Treat plugin settings as configuration to inspect, not proof that the site is optimised.

## Content and template decisions

Use meaningful headings, descriptive URLs and internal links that help a reader follow related information. Editors need a brief covering intent, evidence and missing questions, rather than a keyword-density target. Image alternative text should describe useful visual meaning. Empty search, filtered and archive states need deliberate handling.

Ensure titles, canonicals, sitemap entries and redirects agree on preferred URLs. Check for staging noindex settings after launch. A robots disallow is not private-data protection or a guaranteed way to remove a URL from search. Protect restricted records with authentication. Test translated alternatives and reciprocal hreflang where used.

## Commerce and structured data

Product schema, visible price, currency and availability must reflect the same catalogue source. Keep Merchant Center feeds aligned with product changes. Decide how variants and facets should be discovered and represented. Do not add fabricated reviews or ratings to obtain an enhancement.

Breadcrumbs should reflect understandable relationships, with linked ancestors leading to useful pages. Structured-data validation checks syntax and selected eligibility conditions; the underlying facts still require review. Google determines actual indexing and search presentation.

## Acceptance and maintenance

Inspect the server output and rendered content for representative templates. Check real 404s, relevant redirects and crawlable navigation. Review mobile content parity and field performance. Record editorial ownership so important pages can be updated as services or product data change.

For migration, retain valuable URLs when practical and produce a redirect map for relevant replacements. Test the deployed pages, not only a staging screenshot. See [migration guidance](maintenance-and-migration.md) and [Google's canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls). This document does not initiate indexing submissions or request access to another account.
